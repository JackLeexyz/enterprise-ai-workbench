# 独立服务器部署示例

## 范围与状态

本文使用 `workbench.example.com` 作为占位主机名，需替换为部署者拥有且已核验的独立子域名。采用独立目录、进程、数据和账号，不修改其他站点或应用数据库。部署前必须取得目标服务器及域名的操作授权。

**部署模板尚未完成真实服务器验收。** 操作系统、资源、端口、域名、证书及已有服务均须在目标环境确认，不能假设模板路径或服务已经存在。保留主机指纹校验，不关闭安全检查。

以下步骤只供具备授权访问的操作者执行。示例主机名不是在线演示地址。

## 发布前检查

1. 执行随包 `deploy/preflight.sh` 的只读检查，核对操作系统/Python版本、内存/磁盘、监听端口和已有服务。按实际服务清单检查已有站点及应用入口并保留HTTP状态/截图，不能只看主站首页。
2. 检查4180确实空闲；不空闲则给本应用改端口并同步服务/Nginx，不杀占用者、不覆盖原配置。确认主机防火墙只需既有80/443，**4180不对公网开放**。
3. 核实workbench现有DNS记录和用途。只有不冲突才增加该主机的A记录；不删除已有记录，不假定主域名证书覆盖子域名。若目标被占用，采用另一个明确未使用的子域名并同步所有配置。
4. 白名单发布包不含本机data/private/会话/凭据/客户资料，核验旁置manifest的SHA256。不能把本机登录信息文件上传到网站静态目录。

## 默认部署方式

优先采用现有主机可维护的systemd+独立Python虚拟环境；Docker为备选，两种方式只能启动一套。没有K8s、S3或本机大模型推理。本批384MiB/0.75核上限只是初始隔离配置，未做负载验收，需按RSS/延迟/错误日志调整。

规划路径：代码 `/opt/bolai-workbench/releases/<release>/`，只读符号链接 `/opt/bolai-workbench/current`；每个release自己的`.venv`；数据 `/var/lib/bolai-workbench/workbench.db`；口令文件 `/var/lib/bolai-workbench-private/login.json`；环境 `/etc/bolai-workbench.env`；非root用户 `bolai-workbench`；服务 `bolai-workbench.service`，回环4180。这些是计划路径，不是已存在的远端事实。

首次安装由授权操作者按以下顺序执行，先检查同名路径/账号确属本项目，冲突时停止：

1. 建立专用system用户与release目录，解压白名单包；代码root持有，服务只读。建立独立数据目录（专用用户、0700）与root私有凭据目录（0700）。不要迁入主站/PMS数据或.env。
2. 在release下创建`.venv`并安装`requirements.txt`，运行后端测试；不全局pip升级。依赖安装需可用网络和可信镜像，未经本轮验证。
3. **仅首次**用该release的Python执行`setup_app.py --database /var/lib/bolai-workbench/workbench.db --credentials-out /var/lib/bolai-workbench-private/login.json`，随后将数据库所有权给专用服务用户、权限0600。初始化拒绝已有账号/口令文件，不应删库绕过。
4. 人工核对当前链接后将其指向新release，保存上一release路径。环境文件采用`env.example`，权限0600；其不含模型密钥。复制service模板，`systemctl daemon-reload`，仅启动本应用服务。
5. 内部验活：替换示例域名后执行 `curl --fail -H 'Host: workbench.example.com' http://127.0.0.1:4180/api/workbench/health`。该命令只能验证存活与模式；随后须走真实登录/写入/读取和服务重启后的持久性检查。

更新已有实例前，用`backup.py`做SQLite一致性备份，并核对当前release、服务状态、数据版本。不得重新初始化或用包内虚构样本替换已有数据。

仅在独立虚构资料演示实例中，可将环境项`WORKBENCH_DEMO_LOGIN=1`启用账号选择、可选7天会话与8字符新密码下限。默认0仍为20字符/8小时。该开关不能通过请求参数开启，不创建默认账号或免密入口；普通部署保持关闭，关闭后新登录不再延长，已有长会话如需立即撤销应由管理员明确停用/重置或另行授权注销。

## DNS TLS 与反向代理

0.8.0增建artifact_sharing，旧稿无设置时保持仅自己/version=1，不改原稿或审阅。新代码的只读共享、历史隔离和导出限制依赖新逻辑；禁止旧版并行写库。此次迁移仅隔离库测试，真实库未执行。升级仍先停本应用/一致性备份，不执行setup，不影响主站/PMS。共享授权包含后续修订，不能把正文摘录的披露风险混同为来源ACL已开放；界面必须保留作者确认。

使用新主机名的独立Nginx server块，沿主机已有include方式新增，不重写主站整份配置。DNS确认解析到授权主机后，先按`nginx-workbench-acme.conf.template`为该主机提供独立ACME webroot，其余路径503；此阶段不开放登录表单。

通过主机已有证书管理方式为**确切子域名**签发证书；若已有Certbot可采用单独webroot，不改变主站/PMS的域名清单或续期配置。证书路径必须核实，不能直接假设模板路径存在。签发方式、联系邮箱、CA要求和服务器网络在本轮未验。

随后用`nginx-workbench.conf.template`替换仅本子域名的临时块，先`nginx -t`，通过才reload。不要同时启用临时与最终的两个同名80块。代理保持原Host并设置可信X-Real-IP；仅systemd回环代理模式使用`--trust-proxy`。Docker未信任转发IP时登录限流按代理地址汇总，是安全但更严格的演示限制。

HTTP跳HTTPS；Cookie为host-only/HttpOnly/Secure/SameSiteStrict，不复用原站登录；代理上限3MiB，应用普通JSON仍≤512KiB，文件请求≤2MiB+64KiB、文件≤2MiB。不开放无认证原始资料目录，没有外部模型端点。不得将真实客户文件当演示样本上传。

## Docker备选

Dockerfile/compose已编写，但**未构建、未启动、未验证Docker版本兼容性或容器内存**。仅在已选择此路径的授权主机执行：

```bash
docker compose build
docker compose --profile setup run --rm setup
WORKBENCH_ORIGIN=https://workbench.example.com docker compose up -d workbench
```

setup是显式一次性初始化任务，无网络；主服务只挂载数据卷，不挂载口令卷。随机凭据在独立`workbench-private`卷的`login.json`，只能由授权操作者导出到受控0600文件，不能cat到共享日志或放公网。重复初始化会拒绝，不删卷重试。只发布宿主回环端口；不要把ports改为公网4180。不要与systemd版同时占用端口。

## 备份与故障处理

```bash
python3 deploy/backup.py --database /var/lib/bolai-workbench/workbench.db --directory /var/backups/bolai-workbench
```

使用SQLite backup API取得一致性副本，不直接复制正在写入的主库漏掉WAL。备份含私人内容和会话，0600，目录0700，不放静态服务目录；另需磁盘/备份保留策略。本轮未配置定时任务、监控通知或外部备份。

故障排查：先检查本应用的health、service状态与日志，再查回环端口/磁盘/数据库完整性/权限。HTTP403优先查准确Origin与Cookie/CSRF，不关闭校验；409保留用户草稿，不强制覆盖。无法启动仅停本服务，不重启主站/PMS或整台主机。

回滚先保留当前数据库快照和日志；代码可切回上一个已知release与其虚拟环境，再重启本服务。数据库恢复需操作者确认可接受的数据回退，不能自动覆盖、清空或删除WAL。DNS/证书错误先停新域名发布，不影响原站路由。

## 上线验收记录必须补齐

- 实际域名解析/证书SAN及有效期/HTTP跳转/Host隔离。
- 双账号草稿→保存→审核→导出，退回→新修订→重提，旧审核失效。
- DOCX/TXT/MD上传→排队解析→预览→确认私有草稿→另行发布；损坏文件失败、重试上限、同账号去重、进程中断恢复与跨账号原件权限。
- 取消等待后台确认、原件保留/额度不变、恢复额度检查；明确勾选删除仅未入库文件，回读额度且旧上传请求不能复活，已入库原件保持可下载。
- 私有资料与不可读文档404；撤回后检索/历史摘录/导出阻断。
- 任务预览不落库、确认幂等、负责人处理、重启后记录仍在。
- 账号创建/启停/两角色/重置，旧会话即时失效、重新启用不恢复旧token；并发降级保留最后有效管理员。自我重置后重新登录，密码不回显/不进日志，管理员不能读员工私有正文。
- 分类新增/改名/停用、过时选项重选、默认其他保护；历史原文/版本/引用不被分类操作改写。旧库升级前后账号/来源/修订保持，重启不复活停用目录。
- 桌面/手机真实浏览器截图、内容无横向溢出、按钮与输入不重叠。
- 已有站点及应用回归、资源监控、备份完整性及一次受控恢复演练。
- 1/3/10会话阶梯试用，记录响应延迟/错误/RSS和CPU，不以代码测试替代服务器容量结论。
